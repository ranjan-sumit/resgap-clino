**B24 — root cause of the graph always falling back, found and fixed (2026-08-21, prompted by your "test it on the 20B model, I guess problem with bigger model" request).** Tested `build_knowledge_graph()` live against the real AuDHD_1/AuDHD_2 wiki data on `openai/gpt-oss-20b`, isolating the model variable from the rest of the pipeline. It was NOT a bigger-model-specific problem: **every historical saved run this session (all 5) had silently fallen back to the deterministic graph, on both models identically.** Root cause, confirmed by capturing raw stream deltas directly: `pipeline/graph_builder.py`'s `extract_entities_and_relations()` asked for `max_tokens=6000`, but these are "thinking" models that stream a `reasoning_content` phase before any real `content` — on this prompt's actual complexity, reasoning alone measured ~6300 tokens, consuming the entire budget before the model ever started the JSON answer (`finish_reason="length"`, `content=""`). This is a genuinely empty but "successful" API response, not an error — nothing in the pipeline was flagging it as a problem, it just silently degraded to the fallback graph on every run. A secondary issue at a larger budget (16000 tokens): the model occasionally emits syntactically invalid JSON (a missing comma mid-object), which none of `_robust_parse()`'s existing recovery strategies could fix.

Fixed both: `max_tokens` raised 6000→24000 for entity extraction and 3000→8000 for community detection (real measured need was ~17000 tokens combined; 24000 leaves margin for a larger corpus than the one measured). Added retry-once-on-parse-failure to `extract_entities_and_relations()`, mirroring the existing B19 pattern in `gap_detector.py` — a second sample at the same temperature is not guaranteed to repeat a one-off malformed-JSON glitch. 4 new tests (`tests/test_graph_builder_fallback.py`), full suite now 333 passing.

## Key decisions already made (don't re-litigate without a new ADR)

- Architecture: **Option C, Staged Hybrid** (ADR-000) — infrastructure introduced per-phase, not upfront.
- Product name **"Clinova Research Intelligence Platform"**, tagline **"Evidence → Gaps → Hypotheses → Studies"**, landing headline **"Find the research nobody has done yet"** — all three live in a branding config layer, never in engine code (ADR-004-adjacent, `03-system-architecture.md` AD-3).
- False Novelty Rate is the single highest-priority product metric — missing a real gap is preferred over inventing a false one, everywhere thresholds are tuned.
- Vector DB: Qdrant (ADR-001). Graph: Neo4j CE + NetworkX hybrid (ADR-002). Workflow engine: deferred, no Temporal until a real trigger (ADR-003). Model gateway: three separate provider ports, `azure_client.py` becomes `LLMProvider`'s first adapter (ADR-004). Artifact versioning: bespoke Postgres registry, MLflow scoped out by default (ADR-005). Determinism: bounded, measured via Repeatability Score, never claimed as full determinism (ADR-006). Reference resolution: DOI→PMID→OpenAlex→S2→normalized(title+author+year), five-status trust model (ADR-007). Gap confidence: Search Coverage Score gates every terminal status — a poorly-covered search can never resolve to `OPEN` (ADR-008).
