- (decision) Why: pain-to-solve + mandate-to-meet. ResGap's paper-to-hypothesis pipeline produces gap-detection and computational-modelling outputs that look rigorous but are not trustworthy in their current form (naive cross-paper statistical pooling, unfiltered LLM-invented parameters, a rate-limited/blind academic-validation step, no caching), confirmed via direct code inspection and live-reproduced bugs. Fixing this is required before the tool's outputs can be relied on.
- (capability) CAP-1 Content-addressed caching layer -- intent: pipeline skips re-calling LLM/external APIs for a paper, reference, parameter-set, or gap already resolved in a prior run. success: re-uploading a previously-processed paper or a previously-enriched shared reference produces a cache hit (no corresponding LLM/API call), not a full recompute.
- (capability) CAP-2 Resilient, correctly-scoped academic-API validation -- intent: a gap's open/partial/solved validation status reflects a genuine search result, not a silently-swallowed API failure. success: a 429 from Semantic Scholar triggers a visible retry rather than an immediate silent no-relevant-papers-found; an arXiv query for a well-covered topic returns topically relevant results, not off-topic noise.
- (capability) CAP-3 Explicit success/failure signaling at the LLM boundary -- intent: a pipeline stage can distinguish the LLM genuinely returning no data from the LLM call itself failing, and react differently. success: a forced LLM-call failure produces a distinct, visible failure state at the calling stage rather than silently degrading through the same path used for genuine empty extraction.
- (capability) CAP-4 Confidence-gated, properly-pooled computational modelling -- intent: a simulated risk/outcome estimate reflects real measured data with statistically valid cross-study pooling, not LLM-invented numbers or naive multiplication of unrelated studies' ratios. success: a confidence:low parameter is excluded from simulation and listed separately; cross-paper odds-ratio combination produces a random-effects pooled estimate with an appropriately wider CI, not the naive-multiplication result.
- (constraint) Must not restructure the existing pipes-and-filters pipeline (app.py orchestrating dict-in/dict-out pipeline/*.py filters) -- all four capabilities wrap around it, per architecture spine AD-1.
- (constraint) Cache keys must include domain scoping (for domain-conditioned stages only: wiki pages, gap validations) plus a stage-logic version tag, per AD-3 -- rules out content-hash-only keys.
- (constraint) Result-type fix (CAP-3) is scoped to the LLM client boundary only, not propagated through every pipeline stage, per AD-4 -- rules out a pipeline-wide Result-typed rewrite.
- (constraint) No new infrastructure or database technology -- SQLite gains tables only, pooling is hand-built on existing scipy/numpy pins, only new package is tenacity -- rules out introducing Redis/a new DB/a new heavy stats library.
- (note) Non-goals (from architecture spine Deferred): circuit breaker (pybreaker) integration; Result-type propagation beyond the LLM boundary; concurrent/multi-user cache access; any deployment/infrastructure/hosting change; cache eviction/retention policy.
- (decision) Success signal: re-running ResGap on an overlapping paper corpus costs meaningfully fewer LLM/API calls than the first run (cache hits observable), and a generated report's validation section and simulation numbers can be trusted at face value -- without the kind of manual live API testing this project needed to uncover their current unreliability.
